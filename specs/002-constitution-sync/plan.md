## Summary

The project constitution was amended to v1.1.0 (adding Principle VI — Pre-Release
Iteration and Discovery — and clarifying that Keycloak is deferred to a later
release) and then v1.1.1 (clarifying that first-release auth is HTTP Basic Auth
at the Apache edge with `AuthBasicProvider ldap`, forwarded to Flask as
`X-Remote-User`). Both Sync Impact Reports flagged downstream artifacts as
"pending". This feature propagates those decisions into the repo's docs, inline
code comments, and dependency manifest so that a new contributor, a deployment
operator, and a future maintainer all see a consistent, constitution-aligned
story without having to re-read the constitution themselves.

**Technical approach**: Documentation-and-markers only. No runtime behavior
changes. Edit `README.md`, `flask_backend/README.md`, `flask_backend/app.py`
(inline comments at the two Keycloak code sites), `flask_backend/requirements.txt`
(comment), and three `docs/*.md` files. Do not delete the Keycloak integration
— mark it as deferred per the 001-mark-fhir-unused precedent. Every edit is
traceable to a specific constitution decision via an addendum in the PR
description.
